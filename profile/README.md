<p>第 1 天的账号和第 100 天的账号，在出口上的待遇不该一样。新号还在建立信任，经不起频繁换 IP；老号已经稳定，迁出口反而要挑窗口。很多人把两者放在同一套规则里管，结果是新号被折腾得不稳，老号被牵连着掉登录。这篇按时间轴走：T+0 到 T+7、T+8 到 T+30、T+31 到 T+90、以及之后的稳定期，每个阶段给出口策略、操作节奏和检查项。</p>

<h2>一、把"新号"和"老号"放回时间轴上</h2>
<p>先给个可操作的定义：注册 30 天内算新号，30 到 90 天算过渡，90 天以上且有连续使用记录算老号。这个划分不是平台标准，只是为了便于管理。分期之后你会发现，很多争议其实是阶段错配——用老号的节奏要求新号，或者用新号的谨慎程度对待老号，都会浪费成本。</p>
<p>另一条线是账号价值：主力账号无论新老都按最保守的策略走，测试账号无论新老都可以随意些。所以真正决定策略的是两个维度：账号年龄和价值。下面按年龄讲，价值维度各自往里套。</p>

<h2>二、T+0 到 T+7：新号第一周的出口与环境</h2>
<p>第一周的核心是稳定，不是多样。出口选定之后七天内不要换，环境（浏览器 profile、时区、语言）也不要改。这一周内建议只做正常使用：登录、改一次设置、发起几次对话、看看文档，把使用曲线拉成一条平缓的线。不要在第一天就批量操作，也不要在第一天就挂上自动化脚本。</p>
<h3>出口怎么选</h3>
<p>选一个和目标地区一致的独享静态住宅，绑定之后记录到台账：IP、ASN、rDNS、绑定时间。第一周内每天用 curl -s https://ipinfo.io/json --proxy 你的代理 查一次，确认 country 和 org 没变。共享池在这个阶段不建议用，出口漂移会让第一周的数据全部作废。</p>
<h3>环境怎么配</h3>
<p>一个账号一个浏览器 profile，profile 里固定时区和语言，不要在同一个 profile 里登第二个号。Cookie 让它自然积累，别每天清一次——正常用户不会天天清 Cookie。第一周不要装一堆指纹插件，插件本身也是特征。</p>

<h2>三、T+8 到 T+30：过渡期最容易踩的两件事</h2>
<p>第一个坑是急着扩容：看新号没出问题，立刻在同一出口上加第二个号。同出口加号的关联强度前面说过，这个阶段账号还没积累足够的历史，一旦被并簇，后面很难拆开。第二个坑是频繁改配置：今天换时区，明天换语言，后天换 DNS，每次都留下一条改动痕迹。</p>
<h3>什么时候可以开第二个号</h3>
<p>建议满足三个条件再开：新号连续使用满两周、期间没有触发过验证、出口 IP 两周未变。三条都满足，说明这个出口对这个账号是稳定的，此时再给第二个号单独配一个出口，两个号不同 IP 不同段，彼此不干扰。</p>

<h3>过渡期的操作节奏</h3>
<p>把使用时段固定在当地白天，每天两到三次，每次二十到四十分钟。避免凌晨集中操作，也避免一整天不用然后突然连续八小时。节奏这件事没有硬指标，但"像个人在用"是最低的合理性要求。</p>

<h2>四、T+31 到 T+90：老号迁出口的窗口期</h2>
<p>老号迁出口是有必要的，比如原出口被标记、服务商要回收段、或者业务要换地区。迁的时候挑窗口：避开账单日前后三天，避开每月的使用高峰，挑一个当地工作日的上午。迁移当天只做登录和几次普通对话，不要叠加其他变更。</p>

<h3>迁移的具体步骤</h3>
<p>第一步，新出口先验证：ipinfo 查国家与 ASN、whois 查归属、ping0 看风险分，三项通过再进入下一步。第二步，切代理，登录一次，看是否触发验证。第三步，观察 72 小时，这三天不要做敏感操作。第四步，确认稳定后更新台账，把旧出口标记为释放。</p>
<h3>迁移失败怎么回退</h3>
<p>如果 72 小时内出现两次以上验证，回退到原出口，等两周再试。回退不是失败，是控制损失。最糟的做法是连续换三四个出口试，每个都只试一天，账号在短期内留下大量异地登录记录。</p>

<h2>五、稳定期：新老号并行时的日常节奏</h2>
<p>稳定期的管理重点是"少动"。出口固定、环境固定、使用节奏固定，唯一要做的定期动作是体检：每周查一次 IP 归属，每月看一次流量曲线，每季度跑一次完整自检。异常出现在体检里，比出现在账号上要好。</p>
<h3>新老号并行的三条纪律</h3>
<p>一是不同账号不同 profile，任何时候不在同一个浏览器里切号；二是不同账号不同出口，至少不同 IP；三是新号的试用性操作不要用老号的出口，避免把不确定性传导给稳定账号。</p>
<h3>什么信号说明该检查了</h3>
<p>验证码频率从每周一次变成每天一次、掉登录开始出现、订阅页面加载异常、邮件里出现新设备登录提示——这四个信号任意一个出现，先查出口，再查环境，最后查行为。顺序错了会浪费时间。</p>

<h2>常见问答</h2>
<h3>新号第一周能不能用共享住宅池？</h3>
<p>答：不建议。共享池出口会漂移，第一周本来是用来建立稳定记录的，漂移会让这段记录失去意义。等账号稳定后再考虑用共享池做低成本测试。</p>
<h3>老号一定要迁出口吗？</h3>
<p>答：不一定。出口稳定、使用正常、体检没问题就不动。迁移动机应该是原出口出了问题或有明确业务需求，而不是"听说要定期换"。</p>
<h3>新号和老号能用同一个 C 段的不同 IP 吗？</h3>
<p>答：不建议。同段意味着同邻居，新号的不确定性容易传导给老号。条件允许就让两者落在不同 ASN 或至少不同 /24。</p>
<h3>迁移窗口选在账单日附近会有什么影响？</h3>
<p>答：账单日前后本身就有扣款、发票邮件等动作，再叠加出口变更，出问题时很难判断是哪件事引起的。错开三天，排查会简单很多。</p>

<h2>合规提示</h2>
<p>本文按时间阶段讨论账号与出口的配合方式，属于账号环境管理的常规做法，不涉及规避平台规则或伪造使用行为。账号的使用应符合平台服务条款与所在地法律法规。</p>
<p>迁移出口、调整环境等操作应基于真实的业务需要，不建议为制造"活跃假象"而进行无实际用途的操作。涉及付费订阅时，付款工具与账号主体信息应保持一致。</p>
<p>文中阶段划分与时间建议为经验总结，仅供参考，不同业务的实际节奏应以自身数据为准。</p>
